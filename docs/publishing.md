# Самостоятельная публикация на GitHub

Архив содержит готовую структуру исходного репозитория. Его можно опубликовать
без статьи: README обозначает экспериментальный статус, а теоретические
утверждения сопровождаются условиями и ограничениями.

1. Распакуйте архив и откройте папку `tt-obstacle`.
2. Укажите желаемое авторство в `CITATION.cff` и `pyproject.toml`. Сейчас там
   нейтральное `tt-obstacle contributors`; личные данные не выдуманы.
3. По умолчанию включена MIT-лицензия. Перед публикацией проверьте, что именно
   её вы хотите использовать, и при желании уточните владельца copyright.
4. Создайте пустой репозиторий GitHub с названием `tt-obstacle`.
5. Загрузите **содержимое** распакованной папки в корень репозитория. Убедитесь,
   что также попали скрытые `.github/` и `.gitignore`. Веб-загрузка одного ZIP
   не разворачивает исходники в структуру репозитория.

Если используете Git, выполните в папке проекта:

```bash
git init
git add .
git commit -m "Initial research release v0.1.0"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/tt-obstacle.git
git push -u origin main
```

Замените `YOUR_ACCOUNT` на свой аккаунт. Если Git попросит имя и email автора
коммита, задайте предпочитаемые значения в его локальной конфигурации.
Эти команды рассчитаны на новый пустой удалённый репозиторий.

В комплекте есть конфигурация GitHub Actions для Python 3.10–3.12. После
загрузки проверьте результат первого запуска во вкладке Actions: локальное
тестирование не означает, что удалённый workflow уже прошёл.

Для описания репозитория подойдёт:

> Research tools for feasibility-preserving tensor-train approximation of discrete obstacle problems.

После публикации можно добавить настоящий URL репозитория в `CITATION.cff`
и раздел `[project.urls]` файла `pyproject.toml`. Затем при желании создайте
релиз `v0.1.0`. DOI или размещение пакета на PyPI не нужны для публикации
исходного кода.
